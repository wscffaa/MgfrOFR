# reidmamba 创新筛选

> **项目**: reidmamba
> **Baseline**: MambaOFR
> **结论**: 保留 `MGFE` 与 `RATR`；淘汰 `OverlapPatchEmbed`、`GeneralizedMean`、`TokenFusion`

## 筛选标准

| 维度 | 权重 | 说明 |
|------|------|------|
| 与 `MambaOFR` 兼容性 | 35% | 是否能在不破坏现有双向 Mamba 主干的前提下接入 |
| 对老电影修复的收益潜力 | 30% | 是否有望增强多尺度损伤建模与时空一致性 |
| 实现成本 | 20% | 迁移时是否需要重写大量核心合同 |
| 可验证性 | 15% | 是否能设计清晰的 ablation 和冒烟验证 |

## 候选清单

| 候选 | 角色判断 | 结论 |
|------|----------|------|
| `MGFE` | 核心结构创新 | 保留 |
| `RATR` | 核心训练创新 | 保留 |
| `OverlapPatchEmbed` | 输入 token 化工具 | 淘汰 |
| `GeneralizedMean` | 池化备选算子 | 淘汰 |
| `TokenFusion` | `MGFE` 内部融合细节 | 淘汰 |

## 详细评分

### 创新点 A: MGFE

| 维度 | 评分 | 理由 |
|------|------|------|
| 与 `MambaOFR` 兼容性 | `9.5/10` | 论文实现本身就是共享 Mamba 主干后分叉，天然适配 `MambaOFR` 的双向 `MambaIR` body。 |
| 修复收益潜力 | `9.0/10` | 老电影修复同时需要大结构、局部划痕、闪烁区域的多粒度建模，`MGFE` 正好补单粒度表征缺口。 |
| 实现成本 | `7.5/10` | 需要 `4D feature map <-> token sequence` adapter，但不必推翻基线主体。 |
| 可验证性 | `8.5/10` | 可直接做 `A0/A1/A3` 对比，并检查不同 `G`、`M`、fusion 策略。 |
| **综合** | **8.8/10** | **保留，作为主结构创新** |

### 创新点 B: RATR

| 维度 | 评分 | 理由 |
|------|------|------|
| 与 `MambaOFR` 兼容性 | `7.5/10` | 它只消费多分支特征，但 OFR 需要重新定义正负样本集合。 |
| 修复收益潜力 | `8.0/10` | 多分支特征如果没有显式去冗余，容易退化成重复分支；`RATR` 正好解决这一点。 |
| 实现成本 | `6.5/10` | 公开代码未提供显式 loss，需要按论文公式重写并做数值稳定处理。 |
| 可验证性 | `7.5/10` | 可通过 `A0/A2/A3` 隔离验证，同时记录分支间排序相关性下降是否成立。 |
| **综合** | **7.5/10** | **保留，作为训练期正则创新** |

### 淘汰项评分

| 模块 | 综合评分 | 淘汰原因 |
|------|----------|----------|
| `OverlapPatchEmbed` | `4.8/10` | 属于输入嵌入工具，论文没有把它当核心贡献；OFR 端也已有稳定特征入口。 |
| `GeneralizedMean` | `5.2/10` | 只是 Fig.5 的对比池化策略之一，且论文最终选择的是 `max`，不是 `GeM`。 |
| `TokenFusion` | `6.3/10` | 它只能作为 `MGFE` 内部超参数存在，单独抽出来会把方法拆碎。 |

## 筛选结果

### 保留（进入后续设计）

1. **MGFE**：负责把单粒度 Mamba 特征扩展为 coarse-to-fine 多分支表示。
2. **RATR**：负责在训练阶段压低多分支排序相关性，防止多分支学成同一件事。

### 淘汰

| 创新点 | 淘汰原因 |
|--------|----------|
| `OverlapPatchEmbed` | 只是 token 化入口，不是论文创新主体。 |
| `GeneralizedMean` | 只是融合策略候选，且实验并未胜出。 |
| `TokenFusion` | 是 `MGFE` 的内部组件，不宜单独立项。 |

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| OFR 没有 ReID 的身份标签 | 用光流对齐的时空对应位置定义正样本，用非对应区域/帧定义负样本。 |
| 多分支数过大导致显存增长 | 首轮固定 `G=3`，只做 `A0/A1/A2/A3` 四个变体。 |
| `D-KTau` 数值不稳定 | 用 `tanh((x_i-x_j)/tau)` 公式实现，并先在小 batch 下检查 `isfinite()`。 |
