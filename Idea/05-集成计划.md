# reidmamba 集成计划

> **项目**: reidmamba
> **Baseline**: MambaOFR
> **目标方法**: MGFROFR
> **核心模块**: MGFE + RATR

## 0) 目标与范围

- 目标：在 `MambaOFR` 上引入多粒度特征提取与排序感知正则，形成 `MGFROFR`
- 代码范围：
  - `framework/basicofr/archs/ideas/reidmamba/`
  - `framework/basicofr/losses/`
  - `framework/basicofr/models/`
  - `framework/options/train/mgfrofr/`

## 2) 模块设计与挂载点

### 模块 A: MGFE

- 输入：单方向传播特征 `feat_prop`，形状 `(B, C_f, H, W)`
- 中间表示：`(B, H*W + M, C_f)` restoration token 序列
- 输出：
  - 重标定后的 `feat_prop`
  - 多分支描述向量 `branch_feats`
- 挂载点：`framework/basicofr/archs/mambaofr_arch.py:186,218`
- 参考来源：`projects/001-reidmamba/ref_code/reidmamba.py:199-316`

### 模块 B: RATR

- 输入：`branch_feats`，建议形状 `(B, T, G, D)`
- 输出：标量正则项 `l_ratr`
- 挂载点：训练模型的 `optimize_parameters` 中，参考 `framework/basicofr/models/wavemamba_model.py:27-33,129-138`
- 参考来源：`projects/001-reidmamba/ref_latex/GranRankMamba.md:141-185`

## 3) 消融矩阵

| 变体 | `use_mgfe` | `use_ratr` | 说明 |
|------|:----------:|:----------:|------|
| `A0` | `false` | `false` | `MambaOFR` 原始基线 |
| `A1` | `true` | `false` | 仅验证多粒度结构增益 |
| `A2` | `false` | `true` | 仅验证训练期排序正则是否有独立收益 |
| `A3` | `true` | `true` | 完整 `MGFROFR` |

## 4) 配置字段落点

```yaml
network_g:
  type: MgfrOFR
  use_mgfe: true
  mgfe_num_tokens: 12
  mgfe_num_branches: 3
  mgfe_token_fusion: max

train:
  use_ratr: true
  ratr_loss_weight: 1.0
  ratr_opt:
    type: RATRLoss
    tau: 0.1
    intra_weight: 1.0
    inter_weight: 1.0
```

## 5) 最小可验证路径

1. 语法检查：`python -m py_compile framework/basicofr/archs/ideas/reidmamba/mgfrofr_arch.py framework/basicofr/losses/ratr_loss.py framework/basicofr/models/mgfrofr_model.py`
2. 导入检查：`python -c "from basicofr.archs.ideas.reidmamba import MgfrOFR"`
3. 形状检查：用 `(1, 5, 3, 128, 128)` 的假输入验证输出仍为 `(1, 5, 3, 128, 128)`
4. 损失检查：`use_ratr=true` 时 `l_ratr` 有限且可反向
5. 消融检查：`A0/A1/A2/A3` 四个配置都能启动训练

## 6) 错误预警

| 错误 ID | 触发条件 | 预防措施 |
|---------|----------|----------|
| `E-MGFE-SHAPE` | restoration token 数与 `H*W` 展平顺序不一致 | 把 token adapter 单独做单元测试，固定 reshape 顺序。 |
| `E-RATR-NAN` | `tau` 过小或排序差值过大 | 先做 `tau=0.1` 的基线实现，并在 loss 内部加 `clamp`。 |
| `E-CONTRACT` | 前向返回值破坏 `RTNGANModel` 训练逻辑 | 额外 branch feature 放到可选返回结构或模型缓存，不改默认输出。 |

## 7) 结论

本轮 `diff_plan` 只保留两条主线：`MGFE` 负责结构增益，`RATR` 负责训练期多样性约束。其余工具模块不再单列，避免把方法拆成一堆不构成论文贡献的零件。

## 变体对比关系

> 本节由 W36（`scripts/_w36_append_comparison_target.py`）从 `Idea/ablation_matrix.json.variants[].comparison_target` 自动同步，作为 05 集成计划对"每个变体对比哪个目标、验证什么假设"的统一补充。若本节与 matrix JSON 不一致，应以 **JSON 为准**（JSON 是 SSOT），重跑本脚本即可覆盖。

| 变体 | 对比目标 | role | 验证假设（tests） |
|------|:-------:|:----:|------------------|
| `A0` | `—（baseline）` | baseline | 提供纯 MambaOFR 基线参照，用于所有 ablation 的定量对照。 |
| `A1` | `A0` | ablation | 隔离验证 MGFE 的结构收益（MGFE 单独加入带来的 PSNR 增量）。 |
| `A2` | `A0` | ablation | 隔离验证 RATR 的训练期正则收益（无 MGFE 时 RATR 是否仍带来改进）。 |
| `A3` | `A0` | full | 验证 MGFE 与 RATR 的组合收益，是完整方法配置；对照 A1/A2 检验互补性。 |
| `G1` | `A3` | auxiliary | MGFE 粒度敏感性 (low)：4 tokens / 1 branch 下 MGFE 是否退化到不如 A1 的多 token 多分支效果。 |
| `G2` | `A3` | auxiliary | MGFE 粒度敏感性 (mid)：8 tokens / 2 branch 介于 G1 与 A3 之间，验证 tokens/branches 对性能的连续影响。 |
