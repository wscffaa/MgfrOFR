# reidmamba 框架对齐

> **项目**: reidmamba
> **方法名**: `MGFROFR`
> **Baseline**: `MambaOFR`
> **目标架构类**: `MgfrOFR`

## 0) 方法名与 Baseline

- 方法名：`MGFROFR`（Multi-Granularity Feature Restoration for OFR）
- 核心创新：`MGFE` + `RATR`
- Baseline：`MambaOFR`
- 选择理由：论文本体就是纯 Mamba 架构；`MambaOFR` 已有双向 `MambaIR` body，可直接承接多粒度分支和训练期排序正则。

## 1) 代码范围与落点

- 架构侧：`framework/basicofr/archs/ideas/reidmamba/`
- 损失侧：`framework/basicofr/losses/`
- 模型训练侧：`framework/basicofr/models/`
- 配置侧：`framework/options/train/mgfrofr/`

`RATR` 是训练期 loss，不可能只靠改架构文件完成；如果仍把改动范围限制在纯 `archs/`，那只是文档自欺欺人。

## 3) 形状与数据流

- 输入：`lrs`，形状 `(B, T, C, H, W)`
- `MambaOFR` body 输出：每个时间步的 `feat_prop`，形状 `(B, C_f, H, W)`
- `MGFE` 适配：
  - `feat_prop -> flatten -> tokens`，得到 `(B, H*W, C_f)`
  - 追加 `M` 个 restoration token，得到 `(B, H*W + M, C_f)`
  - `G` 个分支按 `2^g` 融合 restoration token，并各自经过轻量 SSM 头
  - 各分支输出共享维度的描述向量，用于重标定 `feat_prop`
- `RATR` 输入：多分支归一化描述向量，建议组织为 `(B, T, G, D)`
- 输出：保持 `MambaOFR` 外部合同不变，仍为 `(B, T, C, H, W)`

## 4) 最小对齐方案

### `MGFE` 对齐

1. 不改 `MambaOFR` 的光流、DCN 对齐与重建头。
2. 只在 `framework/basicofr/archs/mambaofr_arch.py:186` 与 `framework/basicofr/archs/mambaofr_arch.py:218` 之后插入 `MGFE` 适配层。
3. 分支输出只用于特征重标定与训练期监督，不破坏最终重建路径。

### `RATR` 对齐

1. 不把 `RATR` 写进架构主前向的默认返回值，避免影响 baseline 合同。
2. 训练时仅在 `use_ratr=true` 时收集多分支特征并计算附加损失。
3. OFR 侧的正样本定义基于时序对齐位置，负样本定义基于非对应位置或错配帧集合。

## 5) 风险清单

| 风险 | 触发条件 | 预防/修复 |
|------|----------|-----------|
| `4D/5D` 与 token 边界错位 | `feat_prop` 展平和回写时漏掉 `T` 维 | 先在单帧 `(B,1,C,H,W)` 冒烟，再扩展到多帧。 |
| 分支退化成重复表示 | 只上 `MGFE` 不加正则 | 用 `A1/A3` 对比，同时记录分支间排序相关性。 |
| `RATR` 数值不稳定 | `tau` 太小或负样本构造过稀 | 先固定 `tau=0.1`、`rho=1.0`，并做 `torch.isfinite()` 检查。 |
| 训练接口污染 baseline | 默认前向签名被改坏 | 仅在 `MgfrOFR` 子类或包装模型里暴露额外 branch feature。 |
